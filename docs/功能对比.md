# codex-acp 与当前项目功能对比

核对日期：2026-10-15。以**当前工作区代码（含未提交修改）**为准，不代表已发布或 IDEA 已加载的版本。对照项目：[codex-acp](https://github.com/agentclientprotocol/codex-acp)。

标记说明：

- ✅ 已实现：代码已有对应能力，仍需满足表中客户端协商和使用条件。
- 🟡 部分实现：核心能力可用，尚未覆盖对照项的全部行为。
- ⛔ pi 不支持：仅用于已确认 pi 不支持的能力；当前 RPC 缺少接口或尚缺扩展契约不属于此类。本表暂无已确认属于此类的项目。
- ⏸ 暂不必实现：可以开发，但对当前本机 IDEA ↔ pi 适配目标收益有限，属于建议而非技术限制。
- ⬜ 未实现：可通过适配器、pi 扩展或补充后端接口实现；当前 RPC 接口不足也归入此类，具体前置工作见表中边界说明。

| 能力 | codex-acp 对照项 | 状态 | 当前实现与边界 | 实现依据 |
| --- | --- | --- | --- | --- |
| 文件 diff 与 Air patch | 标准 ACP diff、Air Git patch、文件报告 | ✅ 已实现 | 内置 `edit/write` 已支持结构化 diff、文件位置及历史回放；协商后支持 Air patch 和按请求返回的文件报告，含中文、空格、引号等特殊路径及空新文件。展示上限 256 KiB，旧 `write` 历史无快照时无法补回 | `../src/file-diff.js`；`Agent.toolResult`、`sendFileReport`；扩展写入快照 |
| 其他工具的文件变更覆盖 | 命令、MCP、扩展造成的文件修改 | ✅ 已实现 | 协商并请求报告后，通过本轮前后工作目录元数据快照补入新增、修改、删除及重命名路径，含二进制、Git 忽略文件及失败工具副作用；其他工具仅报告路径，不生成 diff。跳过 `.git` 和符号链接目标，每次限制 20000 项／2 秒；扫描失败或超限标注截断。并发外部修改、轮内临时文件、目录外及后台修改存在边界，保留 `declaredComplete: false` | `../src/file-changes.js`；`Agent.prompt`、`sendFileReport`；`test/file-changes.test.js` |
| 终端展示 | 专用终端内容、输出增量、退出码 | ✅ 已实现 | `bash/powershell` 已有 terminal 内容、协商后的输出增量和退出码 | `Agent.terminalUpdate`、工具开始事件映射 |
| 终端交互输入 | stdin | ✅ 已实现 | Air v1 自动启用桥接，通过执行中的补充输入入口发送 `/stdin 文本`（补换行）或 `/eof`；界面待复验。其他客户端启用 `_meta.terminal_input: true` 后，经 `_terminal/input` 向已授权运行的 `bash/powershell` 写入 UTF-8 文本或 EOF，支持 ACP v1/v2；每次最多 64 KiB，保留超时、取消及进程清理。仅模型以 `interactive: true` 调用的命令可输入，其余命令 stdin 为 `/dev/null`，误读 stdin 不会卡住。专用输入框需客户端接入；不提供 PTY，Windows 实机未验证 | `../src/terminal-input.js`、`PiProcess.request`、`Agent.terminalInput`；扩展 shell operations；真实 pi v1/v2 stdin 测试 |
| 结构化计划 | 计划步骤及状态 | ✅ 已实现 | 扩展注册 `update_plan`，发送 ACP `plan`，历史加载也会回放；是否生成计划取决于模型是否调用工具 | 扩展 `update_plan`；`Agent.publishPlan`、`replay` |
| Plan mode | 后端规划模式 | ✅ 已实现 | `plan` 模式同时注入只规划指令并拒绝非内置只读工具，允许 `update_plan`；这是适配器策略，不是操作系统沙箱，也不约束受信任扩展直接产生的副作用 | `Agent.setMode`、`ui`；扩展 `before_agent_start`、`tool_call` |
| Markdown 计划流与审核 | Air `planContentDelta` 及计划审核 | ⏸ 暂不必实现 | 未实现专用计划流或审核交互；已有结构化计划和普通 Markdown 回答，暂不必再增加专用通道。有 Air 审核需求时再补，不能把普通回答直接当作专用计划事件 | 当前发送 `plan` 和普通消息块，未声明 `planContentDelta` |
| 命令、模板和 skills 发现 | 客户端命令列表与补全 | ✅ 已实现 | 调用 `get_commands` 发布 `available_commands_update`；支持 pi 扩展命令、模板、skill，另有 `/status`、`/compact`、`/goal`；过滤内部 `__acp_` 命令。已补充 Air ACP v1 解析器要求的 `input.type: "unstructured"`，v2 使用 `"text"`；更新后需重启 Agent 连接，输入框补全仍待界面复验 | `Agent.publishCommands`、`localCommand` |
| 上下文用量与压缩 | 用量更新、状态查询、压缩生命周期 | ✅ 已实现 | `usage_update`、`/status`、`/compact [要求]`，转发压缩事件并回放压缩历史；未协商压缩能力时使用普通工具展示 | `Agent.sendUsage`、`localCommand`、`compactionUpdate`、`replay` |
| 每轮 token 与会话费用 | 提示用量、累计费用 | ✅ 已实现 | v1 提示响应、v2 完成状态累计本轮各模型请求及自动压缩的 token（含缓存读写），取消时保留已发生用量；`usage_update.cost` 发布 pi 记录的会话累计美元费用，恢复历史后继续累计。上下文用量不可用时不发送该更新；未上报用量时不伪造，不虚构独立思考 token，IDE 展示待复验 | `Agent.recordUsage`、`prompt`、`sendUsage`；`test/session-state.test.js`、`test/protocol.test.js` |
| 每轮独立费用 | 单次提示费用 | ⬜ 未实现 | 尚无每轮独立费用字段；ACP 标准提示用量不含费用，需要另定元数据约定 | `Agent.recordUsage` 当前只累计 token |
| 会话生命周期 | new/list/load/resume/fork/close/delete | ✅ 已实现 | 均有接口；`load` 回放当前分支，`resume` 仅重开，二者均可继续聊天；`fork` 使用 pi clone，保留源会话；允许新分叉使用请求中的 MCP 配置，源会话仍使用原配置；`close` 释放进程，`delete` 删除对应历史文件 | `Agent.dispatch` 及各会话方法 |
| 历史列表与分页 | 标题、更新时间、游标分页 | ✅ 已实现 | 已有标题、更新时间及游标；通过 Air `list.limit` 限制每页数量，未指定时返回全部；游标是偏移量，不是稳定快照 | `Agent.listSessions`；扩展 `__acp_list` |
| 会话改名、归档、订阅 | Air 会话索引管理 | ✅ 已实现 | 主动改名、归档/取消归档、归档筛选、列表订阅/取消订阅；归档写入 pi 会话，订阅每 2 秒轮询，最多 8 个；相关 Air 索引能力在客户端声明 `sessionIndex` 后启用 | `Agent.renameSession`、`archiveSession`、`subscribeList`；扩展 `__acp_archive` |
| worktree 范围与分叉来源 | 跨 worktree 列表、分叉来源 | ✅ 已实现 | `includeWorktrees` 合并查询 Git worktree 会话，非 Git 项目退回当前目录；Air 会话索引发布 `forkedFrom`，由 pi 父会话路径关联 ID；父会话已删除或不在查询范围时省略 | `Agent.readHistory`、`sessionInfo`；扩展 `__acp_list` |
| 指定历史消息分叉 | 分叉点选择 | ✅ 已实现 | 接收 Air `fork` v1，支持助手消息 ID、分段后缀、SHA-256 文本指纹及重复序号；仅从当前分支截取消息所在完整回合（含工具结果），保留源会话；无效或未找到的分叉点明确拒绝，取消时保留源映射 | `Agent.forkSession`、`cloneSession`；扩展 `__acp_fork` |
| 扩展表单交互 | 用户问题、选项、表单 | ✅ 已实现 | 客户端声明 form elicitation 后桥接 pi `confirm/select/input/editor`；无能力时返回取消 | `Agent.ui` → `elicitation/create` |
| 任意 MCP 服务端表单 | MCP elicitation 完整桥接 | ⬜ 未实现 | 尚未实现完整桥接；需补充后端 RPC 事件与响应通道，再接入 `Agent.ui` | 当前 pi RPC 交互契约 |
| URL elicitation | URL 交互与完成通知 | 🟡 部分实现 | 客户端协商 URL 能力后，扩展经事件总线及 fd 3 发起 URL 请求、接收接受/拒绝/取消，并在核实网页结果后发送 `elicitation/complete`；支持 ACP v1/v2、网址校验、会话隔离与取消清理。真实 pi 扩展通道已验证；IDE 展示待复验，任意 MCP 服务端自动桥接未接入 | `Agent.elicitUrl/completeUrl/control`；扩展 `acp:elicitation:url/complete`；URL 单元测试及本机 pi 测试 |
| IDE 内认证与 provider 管理 | 登录、登出、认证状态、provider 配置 | 🟡 部分实现 | 协商后提供终端登录入口，v2 使用 methodId/env 并支持连接登出；复用本机 pi 凭据，模型跨 provider 切换已实现。完整账户及 provider 管理未实现。现有 RPC 没有完整账户管理接口，当前无需另建凭据存储；确需 IDE 登录时再扩展后端 | `initialize`、模型配置及 `set_model`；pi RPC 命令文档 |
| 原生子 agent 会话 | 独立子会话、生命周期及历史 | ✅ 已实现 | 独立持久 pi 会话，继承配置与权限，支持原生生命周期及定向取消/关闭；父历史递归恢复子树，未知结果报告 disconnected；第三方通过事件契约或嵌套工具接入。无持久记录的旧扩展不自动推断关系 | `subagents` / `nativeSubagentSessions`；`../src/tasks.js`；真实 pi 子树恢复测试 |
| 后台任务与定向停止 | Air async tasks、后台命令状态与停止 | ✅ 已实现 | 独立执行进程持久保存状态与有上限的输出；意外退出后恢复原任务查询和停止，不重复执行命令；正常关闭/归档/删除回收任务。按会话校验控制权，不按历史 PID 直接杀进程 | `asyncTasks`；`../src/tasks.js`；`src/task-worker.js`；崩溃恢复测试 |
| ACP v2 | v1/v2 协议路由 | ✅ 已实现 | 按 2026-10-15 上游草案覆盖会话基础协议及已声明能力：初始化、会话与配置、插入确认、前台状态、排队/执行取消、结构化错误、消息和终端回放、授权、工具/diff/计划/压缩摘要；MCP 可选字段可省略。分叉为实验性能力，子会话及后台任务为 Air 扩展。终端认证按客户端能力协商，并支持连接登出；未声明多目录、音频、systemPrompt/NES；不支持的参数会拒绝。草案变更及客户端界面需再验收，详见 README 的 v2 说明 | `../src/protocol.js`；`test/protocol.test.js`；ACP v2 会话回归、上游 Schema 校验及本机 pi 冒烟测试 |
| 额外工作目录 | 多目录会话配置 | ⏸ 暂不必实现 | 当前一个会话一个绝对 `cwd`，未接收额外工作目录配置；暂无多目录配置需求时不必补。它与跨 worktree 历史列表是两项不同能力 | `Agent.newSession`、pi 启动参数 |
| 自定义指令 | Air `customInstructions` | ✅ 已实现 | 协商后接收会话指令并注入 pi 系统提示，分叉保留；未协商时忽略，有类型和长度校验 | `Agent.newSession`、`cloneSession`；扩展 `before_agent_start` |
| 推荐配置值 | Air `recommendedValue` | ✅ 已实现 | 协商后发布初始模型与推理级别为推荐值，用户切换不会覆盖推荐值；不是 pi 原生的动态推荐引擎 | `Agent.modelConfig`、`newSession` |
| 结构化错误与通知 | Air `sessionFailure`、会话通知 | ✅ 已实现 | 协商后提示执行失败返回分类后的 `sessionFailure`；扩展通知在客户端声明 notices 后转发。其他请求保留 JSON-RPC 错误，错误分类基于文本推断 | `Agent.sessionFailure`、提示完成逻辑、`ui` |
| 后端错误精确分类 | 类型化错误逐类映射 | ⬜ 未实现 | 尚未实现可靠的逐类精确映射；需先补充后端类型化错误码，现有文本推断不足以保证精确分类 | 当前 pi RPC 错误数据 |
| 长期 goal 管理 | 设置、暂停、恢复、清除目标 | ✅ 已实现 | `_session/goal` 与 `/goal` 支持四种操作、持久化和恢复，活动目标注入系统提示；暂停不等于取消当前回合 | `Agent.goalSession`、`goalUpdate`；扩展 `__acp_goal`、`__acp_check` |
| goal 自主调度与预算 | 自主续跑、完成判定、预算管理 | ⏸ 暂不必实现 | 需要另建调度与资源控制策略，超出当前目标状态管理范围，暂不增加 | 当前 goal 仅管理状态与提示注入 |
